核心洞察：搜索引擎是最高杠杆

传统学术 API（S2/DBLP）虽然免费但 rate limit 严格，批量使用几乎不可行。真正的突破来自搜索引擎 API —— Serper 1510 次查询在 2 分钟内完成，发现了 1285 个主页，是之前所有学术 API 总和的 5 倍产出。找到主页是整个流程的瓶颈，一旦有了主页 URL，email/GitHub/LinkedIn 的提取转化率极高。

4关键技术细节

决定成败的几个核心算法和策略。

4.1 华人识别 is_chinese()

# 120+ 常见华人姓氏（覆盖 99%+ 常见中文姓） CHINESE_SURNAMES = {'Li','Wang','Zhang','Liu','Chen','Yang','Huang','Zhao','Wu', 'Zhou','Xu','Sun','Ma','Zhu','Hu','Guo','He','Lin','Luo','Gao', ...} # 排除规则：韩国名 (Kim/Park/Choi)、日本名 (Tanaka/Yamamoto)、越南名 (Nguyen/Tran) EXCLUDE_FIRST = {'Hyun','Seung','Ji','Min-', ...} # 韩国名特征 def is_chinese(name): surname = name.split()[-1] # 英文论文中姓在最后 if surname not in CHINESE_SURNAMES: return False first = name.split()[0] if any(exc in first for exc in EXCLUDE_FIRST): return False return True

4.2 贡献分计算

# 平衡第一作者（活跃研究）和末位作者（导师/PI） contrib_score = first_author * 4 + last_author * 4 + second_author * 2 + middle_author * 1 # 筛选阈值：contrib_score >= 3 进入富化管线 # 分布：50+:0, 30-49:1, 20-29:11, 10-19:59, 5-9:324, 3-4:851

4.3 OpenAlex 消歧策略

# 关键发现：?search= 比 ?filter=display_name.search: 效果好 10 倍 # filter 不做相关性排序；search 按总影响力排序 url = f"https://api.openalex.org/authors?search={name}" # 消歧规则： # 1. works_count >= 我们数据中的 paper_count（排除同名低产者） # 2. last_known_institutions 不含 Hospital/Medical（排除医学同名人） # 3. 取 ?search= 返回的第一条结果（已按相关性排序）

4.4 Serper 主页发现

# 查询模板 query = f"{name} {institution} homepage" # URL 分类优先级 # 1. xxx.github.io → homepage + 暗示 GitHub 账号 # 2. people.xxx.edu/~name → 学术主页 # 3. 个人域名 (xxx.com/me/dev/ai) → 个人网站 # 排除：scholar.google, dblp, arxiv, twitter, researchgate # LinkedIn 直接从搜索结果中提取（无需单独搜索） # 实测：1510 次搜索产出 306 个 LinkedIn URL（20% 附带产出）

7实战经验总结

踩过的坑和验证过的最佳实践。

🔍

搜索引擎 > 学术 API

S2/DBLP 的 rate limit 让批量使用几乎不可能。Serper 0.15s/req、无 CAPTCHA，是主页发现的绝对最优解。投入 $2-3 的 API 费用节省了数小时的浏览器自动化。

🎯

先找主页，再提取一切

主页是「信息枢纽」——一旦找到，email(44%)、GitHub(53%)、LinkedIn(23%) 的提取转化率极高。把精力集中在主页发现上，而非逐个搜 email/GitHub。

⚠

OpenAlex ?search= 优于 ?filter=

filter 不做相关性排序，常见名会匹配到医学领域同名人。?search= 按总影响力排序，顶级 CS 研究者自然排在前面。这一个改变将准确率从 60% 提升到 90%。

📊

爬取边际递减严重

首次爬取 email 命中 44%，第二次 32%，第三次 5%。原因：「好爬」的页面（明文 email、简单 HTML）已被消耗，剩下的是 JS 渲染或不公开邮箱的页面。

👨‍💻

github.io 一石二鸟

xxx.github.io 既是个人主页，也直接暗示 GitHub 账号为 github.com/xxx。这让一次搜索同时获得两个字段。约 25% 的研究者主页是 .github.io 形式。

🚫

医学同名人是最大噪声源

OpenAlex 中大量常见中文名被匹配到医学/农业方向同名人。解决方案：当 affiliations 全为 Hospital/Medical 时，直接清除（74 人被修正）。

💾

每 50 条自动存盘

长时间运行的 pipeline 随时可能被中断（网络超时、session 压缩）。每 50 条写盘一次，确保任何中断后都能从断点续跑，不丢失进度。

❓

缩写名是不可解的

E. Zhang / H. Li / Z. Li 等单字母缩写名，即使加上论文标题也很难定位到具体的人。这是搜索引擎的根本限制（约占数据集 2%），接受即可。

9复现指南

如何在其他场景（不同领域/不同人群）复用这套方法。

Step 1 — 数据源准备

确定目标会议/期刊列表

根据目标领域选择顶会，通过 Semantic Scholar API 批量拉取论文（?venue=XXX&year=2022-2024）。缓存到本地 JSON。

Step 2 — 目标人群筛选

定义筛选函数

修改 is_chinese() 为你的目标人群规则（如 is_indian()、is_european() 等）。计算贡献分并设置阈值过滤。

Step 3 — OpenAlex 学术富化

获取 H-Index 和机构信息

使用 ?search={name} + works_count 筛选。注意 SLEEP=0.3s，90% 匹配率。设置 NON_CS_KEYWORDS 排除非目标领域。

Step 4 — Serper 主页发现

批量搜索获取主页 URL

按 H-Index 降序排列，查询 "{name} {institution} homepage"。需要 Serper API Key ($50 可跑 5 万次)。

Step 5 — 主页爬取

提取联系方式

对所有发现的主页执行 HTTP GET + regex 提取。注意 SSL 证书问题和 EXCLUDE 列表。首次爬取产出最高。

Step 6 — Tavily 补充

处理难搜的缩写名

用 Tavily 的 AI 搜索能力 + 论文标题辅助消歧。免费配额 200 次/天，适合小批量精确场景。

Step 7 — 输出与部署

生成可交互的人才图谱

JSON → Excel (openpyxl, 多 sheet) + 交互式 HTML (Talent Insights panel) + GitHub Pages 在线展示。

成本估算

对于一个 2000-3000 人规模的数据集，预计成本：Serper API ~$3（约 3000 次查询）+ Tavily 免费配额 + OpenAlex 免费 + 主页爬取免费。总成本 < $5，约 2-3 小时可完成全流程。唯一的大时间消耗是 OpenAlex 批量匹配（3000 人约 1.5 小时，受 SLEEP 限制）。
